# 本地前后端开发环境启动指南

> 适用范围：在宿主机运行 Python 后端，在浏览器中运行 Vite 前端；PostgreSQL 与 Redis 继续使用 Docker Compose。完整容器化、前后端混合运行的其他组合见 [前后端容器组合测试](前后端容器组合测试.md)。

## 运行拓扑

本地开发不建议在宿主机手工安装 PostgreSQL 和 Redis。推荐只容器化基础设施，后端和前端直接运行本地源码：

```text
浏览器 / Vite（:3000）
        │  同源代理 /api、/ws
        ▼
本地 Python 后端（API :8000、Engine :8001、Trade :8002、Stream :8003）
        │
        ├── PostgreSQL Docker 容器（宿主机 :5432）
        └── Redis Docker 容器（宿主机 :6379）
```

后端统一入口是 `python -m backend.main_oss`。默认的 `SERVICE_MODE=all` 会启动 API、Engine、Trade、Stream 以及一个单进程 Celery Worker。

## 前置条件

- Git、Docker Engine 和 Docker Compose。
- Python **3.10**；推荐使用 Conda，也可使用标准 `venv`。
- Node.js 20+ 与 npm。
- Linux x86_64 / AMD64 是完整本地 Qlib 开发的推荐环境。`requirements/ai.txt` 对 `pyqlib==0.9.7` 设置了 x86_64/AMD64 条件；Apple Silicon 或 Windows ARM 原生环境不会安装 Qlib，应使用 amd64 Docker 或 x86_64 Linux/WSL 环境进行回测开发。
- 至少预留约 8 GB 内存和足够磁盘空间；完整 Qlib 数据、模型和特征快照会占用更多空间。

以下命令均从仓库根目录执行。

## 1. 首次配置 `.env`

项目使用两份环境文件：根目录 `.env` 管理 Compose 与基础设施，`backend/.env` 管理应用。不要将 `DB_HOST`、`REDIS_HOST` 或 `DATABASE_URL` 写入任一文件：本地 Python 会自动使用 `127.0.0.1`，Compose 容器会自动使用 `db`、`redis`。

```bash
cp .env.example .env
cp backend/.env.example backend/.env
```

### 根目录 `.env`：必须修改

下列参数用于创建/连接 Docker 中的 PostgreSQL 和 Redis。请替换模板中的 `CHANGE_ME_...` 值；两处密码必须与后端实际连接的凭据一致。

```dotenv
POSTGRES_DB=quantmind
POSTGRES_USER=quantmind
POSTGRES_PASSWORD=替换为本地强密码
POSTGRES_PORT=5432
POSTGRES_HOST_PORT=5432

REDIS_PASSWORD=替换为本地Redis密码
REDIS_PORT=6379
REDIS_HOST_PORT=6379

# 浏览器版 Web 容器使用；本地 Vite 通常不需要改它
WEB_HOST_PORT=3080

# 本地 CPU 开发保持默认即可
TORCH_DEVICE=cpu
```

若 5432 或 6379 已被占用，只修改宿主机映射端口，例如设置 `POSTGRES_HOST_PORT=15432`、`REDIS_HOST_PORT=16379`。此时还要在 `backend/.env` 显式设置匹配的 `DB_PORT=15432`、`REDIS_PORT=16379`，因为本地后端默认连接 5432/6379。

### `backend/.env`：必须修改

至少替换安全凭据与管理员密码：

```dotenv
APP_ENV=development
DEBUG=true

SECRET_KEY=替换为随机字符串
JWT_SECRET_KEY=替换为随机字符串
INTERNAL_CALL_SECRET=替换为随机字符串
ADMIN_USERNAME=admin
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=替换为本地管理员密码

# 本地浏览器开发默认端口 3000；局域网调试时补充实际前端完整 Origin
CORS_ALLOWED_ORIGINS=http://127.0.0.1:3000,http://localhost:3000,http://127.0.0.1:5173,http://localhost:5173,null

# 没有 AI Key 时仍可启动；AI 策略功能会不可用
AI_STRATEGY_LLM_REQUIRED=false
AI_IDE_LLM_API_KEY=
```

本地运行时，将模板中的 Docker 绝对存储路径改为仓库相对路径，避免 Python 进程尝试写入宿主机 `/data`：

```dotenv
STORAGE_MODE=local
STORAGE_ROOT=./data
MARGIN_STOCK_POOL_PATH=./data/融资融券.json
QLIB_BACKTEST_RESULT_DIR=./data/backtest_results

QM_QUANTDB_DATA_DIR=./data/quantdb
QUANTDB_STATE_DIR=./data/quantdb/.sync_state
QM_QUANTUS_DATA_DIR=./data/quantus
QM_QUANTHK_DATA_DIR=./data/quanthk
QM_QUANTBC_DATA_DIR=./data/quantbc
QM_QUANTFUTURES_DATA_DIR=./data/quantfutures
QM_TDX_DIR=./data/third_party/tdx
QM_INVESTMENT_DATA_DIR=./data/third_party/investment_data
QM_SIMONLIN_A_DIR=./data/third_party/simonlin_a_stock
```

不要在本地 `.env` 中添加 `QUANTMIND_RUNTIME=docker`。如需显式指定运行方式，启动命令中设置 `QUANTMIND_RUNTIME=local`。也不要将 `QUANTMIND_ENV=production` 用于日常开发；生产模式会对内部调用密钥执行更严格的校验。

可选项：需要 AI 策略、AI-IDE 或投研时，在 `backend/.env` 填写 `LLM_API_KEY` 或 `AI_IDE_LLM_API_KEY`（也可使用 `DASHSCOPE_API_KEY` / `QWEN_API_KEY`）；需要跨域局域网访问时，将浏览器实际访问的 `http://IP:3000` 加入 `CORS_ALLOWED_ORIGINS`。

## 2. 启动 PostgreSQL 与 Redis

```bash
docker compose up -d db redis
docker compose ps db redis
```

应等待两个服务均通过健康检查。根目录 `.env` 中的 `POSTGRES_*` 和 `REDIS_PASSWORD` 会同时被容器和本地后端读取；后端的环境加载器会自动把它们转换为 `DB_*`、`REDIS_*` 和 `DATABASE_URL`。

> 修改 `POSTGRES_USER`、`POSTGRES_PASSWORD` 或 `POSTGRES_DB` 不会修改已经存在的 `postgres-data` 卷中的账号和数据库。若已有卷使用旧凭据，请通过 PostgreSQL 管理方式更新账号密码，或在确认数据可丢弃后另行重置开发数据；不要把“重建容器”误认为会重建数据库。

首次后端启动会自动执行建表检查和 OSS 兼容迁移。系统优先调用 `psql`；本机未安装 `psql` 时会使用已安装的 `psycopg2-binary` 回退执行。

## 3. 创建 Python 环境并安装后端依赖

### 推荐：Conda

```bash
conda create -n quantmind python=3.10 -y
conda activate quantmind

python -m pip install --upgrade pip setuptools wheel cython

# 与后端镜像一致的 CPU PyTorch；仅需 CPU 开发时使用此命令
python -m pip install "torch==2.9.1+cpu" --index-url https://download.pytorch.org/whl/cpu

# requirements.txt 只是基础依赖，三个文件都需要安装
python -m pip install -r requirements.txt
python -m pip install -r requirements/production.txt
python -m pip install -r requirements/ai.txt

# 与 Dockerfile 保持一致：数据 SDK 和 TradingAgents 本地包
python -m pip install "quantdb-sdk>=0.2.10"
python -m pip install -e ./TradingAgents-astock "starlette<1.0.0"

python -m pip check
```

### LightGBM 的本机 OpenMP 依赖

在 Ubuntu/Debian 主机直接使用 Conda 或 venv 训练时，LightGBM 仍需要系统 OpenMP 库；首次安装环境后执行：

```bash
sudo apt-get install -y libgomp1
```

缺失时导入 LightGBM 会报 `OSError: libgomp.so.1`。Docker 镜像的训练路径不受此项影响。

### 不使用 Conda：标准 venv

```bash
python3.10 -m venv .venv
source .venv/bin/activate             # Windows PowerShell：.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip setuptools wheel cython

# 后续执行与 Conda 方案相同的 torch、requirements、quantdb-sdk 和 TradingAgents 安装命令
```

### 为什么安装 `requirements.txt` 后仍无法启动？

`requirements.txt` 有意只包含基础 Web、数据库、数据处理和任务依赖；它**不包含 Qlib**。Engine 的回测、策略和推理模块依赖 `qlib`，而 `pyqlib==0.9.7` 位于 `requirements/ai.txt`。只安装第一个文件后出现 `ModuleNotFoundError: No module named "qlib"` 是预期的依赖缺口，不是代码路径错误。

后端 Dockerfile 的实际安装顺序是：PyTorch → `requirements.txt` → `requirements/production.txt` → `requirements/ai.txt` → QuantDB SDK → TradingAgents editable install。本地环境按上一节顺序安装即可最大程度复现镜像。RD-Agent 是可选的独立因子演化组件，不是启动四个核心服务的前提。

## 4. Qlib 安装、补丁与数据

### 验证 Qlib 包

```bash
python -c "import qlib; print(qlib.__version__); print(qlib.__file__)"
```

本项目固定使用 `pyqlib==0.9.7`。不要在未验证回测兼容性的情况下升级 Qlib；不同版本的策略、`reset()` 签名和回测对象可能不兼容。

### 应用本地 Qlib 0.9.7 补丁

镜像构建会修复 Qlib 0.9.7 在停牌/无价格持仓上计算市值时的 `None` 价格异常。仓库中的 `docker/patch_qlib.py` 使用了容器内 Python 路径，不能直接用于 Conda 或 venv。为使本地环境与镜像一致，在确认已安装 `pyqlib==0.9.7` 后执行以下一次性、可重复的补丁：

```bash
python - <<'PY'
from pathlib import Path
import qlib

position_file = Path(qlib.__file__).parent / "backtest" / "position.py"
old = """    def calculate_stock_value(self) -> float:
        stock_list = self.get_stock_list()
        value = 0
        for stock_id in stock_list:
            value += self.position[stock_id][\"amount\"] * self.position[stock_id][\"price\"]
        return value"""
new = """    def calculate_stock_value(self) -> float:
        stock_list = self.get_stock_list()
        value = 0
        for stock_id in stock_list:
            price = self.position[stock_id].get(\"price\")
            if price is not None:
                value += self.position[stock_id][\"amount\"] * price
        return value"""
content = position_file.read_text()
if old in content:
    position_file.write_text(content.replace(old, new))
    print(f"patched: {position_file}")
elif "price = self.position[stock_id].get(\"price\")" in content:
    print(f"already patched: {position_file}")
else:
    raise SystemExit(f"unexpected qlib source, refuse to patch: {position_file}")
PY
```

出现 `TypeError`，且错误栈指向 `qlib/backtest/position.py` 的持仓价格相乘时，优先确认补丁是否执行；不要通过吞掉回测异常来绕过该问题。重新创建虚拟环境或升级/重装 pyqlib 后，需要重新执行补丁。

### Qlib 数据是另一项前置条件

Qlib 包安装成功只代表 Python 能导入回测库；实际回测、模型推理还需要本地 Qlib 二进制数据。默认解析顺序为：

1. `QLIB_PROVIDER_URI`（显式指定时）；
2. `data/quantdb/.qlib_cache/cn_data`；
3. `db/qlib_data`。

可先检查基础文件：

```bash
test -f db/qlib_data/calendars/day.txt && echo "calendar ready"
test -d db/qlib_data/features && echo "features ready"
```

没有数据时，服务可以启动，但回测和需要历史特征的推理会失败或返回无数据。完整数据包的获取与验证参见 [数据包安装指南](数据包安装指南.md)。若数据包中只有 `features_real/`，统一入口会在同一 Qlib 目录创建 `features -> features_real` 的符号链接。


### 本机 Conda 训练

模型训练的本机开发分支复用 `docker/training/train.py`，但由已启动后端的 Conda Python 直接执行，不会创建训练 Docker 容器。`backend/.env` 可保持默认的自动判断，或显式配置：

```dotenv
TRAINING_LOCAL_EXECUTION_MODE=process
TRAINING_LOCAL_API_BASE_URL=http://127.0.0.1:8000
```

`auto` 在 Docker Compose 容器中仍使用既有 Docker 子容器训练，在本机启动后端时使用本地 Conda 进程。直接进程将 `db/feature_snapshots`（快照模式）或 `db/qlib_data`（Qlib Alpha158 模式）传入同一训练脚本，并把模型产物直接写入模型注册目录。若启动配置、数据路径或进程创建失败，任务会写回 `failed`，不会停留在 `provisioning`。

## 5. 启动本地后端

先创建本地可写目录：

```bash
mkdir -p data/uploads data/strategies data/backtest_results data/quantdb logs models user_pools_local
```

然后从项目根目录启动全部核心服务：

```bash
PYTHONPATH=. QUANTMIND_RUNTIME=local SERVICE_MODE=all \
  python -m backend.main_oss
```

首次启动会创建表、初始化连接池并启动多个子进程，可能需要数十秒。看到服务端口监听前不要启动依赖 API 的前端测试。另一个终端中验证：

```bash
until curl -fsS http://127.0.0.1:8000/health; do sleep 2; done
curl -fsS http://127.0.0.1:8001/health
curl -fsS http://127.0.0.1:8002/health
curl -fsS http://127.0.0.1:8003/health
```

仅调试某个服务时可使用：

```bash
PYTHONPATH=. QUANTMIND_RUNTIME=local SERVICE_MODE=api python -m backend.main_oss
PYTHONPATH=. QUANTMIND_RUNTIME=local SERVICE_MODE=engine python -m backend.main_oss
PYTHONPATH=. QUANTMIND_RUNTIME=local SERVICE_MODE=trade python -m backend.main_oss
PYTHONPATH=. QUANTMIND_RUNTIME=local SERVICE_MODE=stream python -m backend.main_oss
```

注意：API 会代理 Engine、Trade、Stream 的部分路由；只启动 API 适合认证和 API 层调试，不适合完整前端联调。`SERVICE_MODE=all` 已包含一个 Celery Worker。如需定时任务，再另开终端启动 Beat：

```bash
PYTHONPATH=. QUANTMIND_RUNTIME=local \
  python -m celery -A backend.services.engine.qlib_app.celery_config:celery_app beat --loglevel=info
```

## 6. 启动前端

前端通常只需要：

```bash
npm install
npm run dev:web
```

该命令在 `0.0.0.0:3000` 启动 Vite，并默认将 `/api`、`/ws` 代理到 `http://localhost:8000`。浏览器访问 `http://127.0.0.1:3000` 或 `http://localhost:3000`。若后端不在本机，用实际地址覆盖：

```bash
VITE_API_URL=http://192.168.1.111:8000 npm run dev:web
```

要启动 Electron 开发模式则使用 `npm run electron:dev`；浏览器联调优先使用 `npm run dev:web`，避免 Electron 缺少系统库时干扰 Vite 的判断。修改 TypeScript 后可执行 `npm run typecheck`。

## 常见问题排查

| 现象 | 首先检查 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: qlib` | 是否只安装了 `requirements.txt` | 安装 `requirements/ai.txt`，并验证 `import qlib`。 |
| Qlib 回测在 `position.py` 报 `NoneType` 乘法错误 | 本地环境是否应用 Qlib 补丁 | 按第 4 节执行补丁；重装 pyqlib 后重做。 |
| `connection refused` 指向 127.0.0.1:5432 或 :6379 | `docker compose ps db redis` | 启动 `db redis`；检查根 `.env` 密码和本地端口覆盖。 |
| 数据库认证失败 | 已有 PostgreSQL 数据卷是否仍使用旧密码 | 不要只重建容器；同步更新数据库角色，或按数据保留策略重置开发库。 |
| `/data` 权限错误或文件写到系统目录 | `backend/.env` 的存储项 | 按第 1 节改为 `./data/...`，并创建目录。 |
| 后端启动但回测无数据 | Qlib 包与二进制数据是两件事 | 检查 `calendars/day.txt`、`features/`，按数据包指南安装。 |
| 浏览器登录/请求被 CORS 拒绝 | 浏览器地址是否在 `CORS_ALLOWED_ORIGINS` | 添加完整 Origin 后重启本地后端。 |
| Vite 请求发往错误的 localhost | 是否手工设置了 `VITE_API_BASE_URL` 或 `VITE_WS_BASE_URL` | 删除这两个变量，使用同源代理；远端后端仅设置 `VITE_API_URL`。 |
| `address already in use` | 8000–8003、3000、5432、6379 是否被占用 | 停止占用进程或调整端口；变更数据库/Redis宿主机端口时同步设置本地后端端口变量。 |
| 训练/AI-IDE 子容器失败 | Docker daemon / socket 是否可用 | 这类功能会创建子容器；先确保 Docker 可用。普通 API、前端和基础回测排查时可暂不启用。 |
